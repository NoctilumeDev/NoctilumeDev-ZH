# 让工程历史可接管：每轮决策与事实记录

> 工程方法札记。它规定怎样留下可复核的施工轨迹，不把文档本身当作事实裁判。

大项目不能只记录“现在是什么”。当前状态告诉接手者站在哪里，却未必告诉他：为什么走到这里，哪些路已经被反例否决，以及下一步为什么有资格开始。聊天上下文可以帮助当轮推理，但不应成为工程的长期真相源。

因此，每个有独立问题、停止线和验收出口的闭环，都应留下一个简短的轮次记录。记录的目标不是复述所有命令，而是让一个没有原对话的接手者能够重新回答：**这轮想证明什么，实际证明了什么，哪些判断仍未取得资格。**

## 三层材料，各负其责

```text
决策与轮次记录  →  为什么选择、准备怎样做、反例怎样改变判断
Git commit / PR →  哪些文件实际改变、变更是否进入主线
CI / 读回 / 工件 →  在哪个精确坐标上，运行与观察实际得到什么结果
```

三层可以互相查证，却不能互相替代。Git diff 能显示改动，但通常不足以解释为什么放弃另一条方案；决策文档能解释理由，却不能代替提交证明代码已经改变；CI 绿色只说明那组门在指定条件下通过，不能自动证明未进入门的声明。

尤其要把“当时准备怎样做”和“后来实际发生了什么”分开写。计划可以在执行前建立；PR 编号、merge SHA、远端门禁和公开读回只能在发生后补入。后来的事实不应悄悄改写原计划，更不能擦掉首次失败。

## 每轮至少留下七件事

1. **问题与边界**：这轮唯一要关闭的接缝是什么；哪些相邻能力明确不在范围内。
2. **起点与理由**：基线的 exact SHA、已冻结输入、为什么这个问题现在阻断后继工作。
3. **预期与反证**：原方案、关键前提、什么证据一旦出现就必须停下或改变方案。
4. **实际轨迹**：有意义的测试、环境、PR、CI、读回结果，按发生顺序记录，包括首次红灯和后来复验。
5. **失效传播**：哪些前提被推翻；依赖它们的合同、状态、测试断言或下一步资格是否一起失效。
6. **变更与证据坐标**：commit、PR head/base、merge 后 exact main、CI run 与 attempt、工件摘要和读回入口。没有公开入口的本地产物只能标为本地诊断，不能冒充公共证据。
7. **落点与停止线**：当前是候选、已审计、已冻结还是仍 held；下一轮允许做什么，禁止直接做什么。

这里的“实际轨迹”不要求把终端输出全部粘进 Markdown。记录应指向原始来源，并准确写出来源能够支持的结论上限。找不到证据坐标时，应降低结论强度，而不是靠叙述补齐。

## 一个小例子：新记录不等于新执行

在 VeriTrail 一次 exact-main [Public CI](https://github.com/NoctilumeDev/VeriTrail/actions/runs/34930110622) 中，attempt 1 是 `10/11 FAILURE`，E3 的 Release 资产下载连续返回 HTTP 500；产品 clean-install acceptance 当时没有运行。后续同 SHA 的 attempt 2 最终显示 `11/11 SUCCESS`。

若只看 [attempt 2 job 列表](https://api.github.com/repos/NoctilumeDev/VeriTrail/actions/runs/34930110622/attempts/2/jobs?per_page=100)，十一个 job 都有新 ID，很容易写成“十一项全部重跑”。但对照 [attempt 1 job 列表](https://api.github.com/repos/NoctilumeDev/VeriTrail/actions/runs/34930110622/attempts/1/jobs?per_page=100) 的开始和结束时间，只有 E3 在第二次窗口内新执行；其余十项沿用首次成功事实。

轮次记录应同时保留：原始 `10/11` 红灯、限定复验的操作、E3 新执行成功，以及同 SHA 的**组合结果** `11/11`。新 job ID 不是“重新执行”的充分证据，复验成功也不倒改首次失败。这个例子说明，文档真正需要保管的不只是终态，还有曾经误判的前提及其纠正依据。

## 给后来接手者的入口

一个新的人或 Agent 不应从文章末尾的“下一步”直接开工。他应先取得当前远端主线，核对工作树与 exact SHA，读取仓库当下的规则、最近轮次记录及其直接依赖，再回查所引用的 commit、PR、门禁和工件。若记录中的基线已经变化，或一个反证条件成立，应先重判其下游结论，不把旧聊天和旧文档的候选当作新主线事实。

最小记录可以采用下面的骨架；没有发生的坐标写 `NOT YET AVAILABLE`，不要提前编造：

```markdown
## 本轮问题与停止线
## 起点：exact base / frozen inputs / 为什么现在做
## 原方案、关键前提与反证条件
## 实际发生：按时间排列，保留首次失败与复验
## 已证、被推翻、仍未知的判断
## 变更坐标：commit / PR / exact main
## 证据坐标：CI run + attempt / readback / artifact digest
## 最终状态与下一轮授权边界
```

这是一份**工程记忆索引**，不是 VeriTrail 的标准 Evidence，也不拥有 Verdict 权。轮次记录解释认知怎样演化；Git 保存变更历史；独立门禁与工件保存可回查的执行事实。三者对齐后，换掉聊天上下文也不会把工程的理由和失败历史一起换掉。

相关的[公共验证闭环法](public-verification-loop.md)讨论事实怎样进入公开平台；[Fresh Checkout 三阶段独立复验](fresh-checkout-independent-audit.md)检验这些公开材料在原对话消失后是否仍能被陌生审查者理解。本篇补的是两者之间的日常动作：**每完成一个最小闭环，就把决策、实际与证据身份一起留下。**
